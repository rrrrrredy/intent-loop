# Bounded v4 grader calibration

This checks six existing synthetic case pairs, not product effectiveness. The interface names `baseline` and `plugin` mean the existing full and without-settled ablation versions respectively. No native-baseline arm, new product conversation, new policy version, new case, or benefit aggregate was created.

The v4 grader and its existing v3-named output schema were used unchanged from commit `9e9c4650d3dc55dba6e41bec878f8958dbc10d79`. Two batches of three cases each completed on OpenAI `gpt-5.6-sol`, low reasoning, read-only sandbox and approval never. Exactly two primary requests were issued; both returned valid structure on the first attempt. There were no remedial or score-driven retries. Frozen manual expectations were written before either grader request and were not sent to the grader.

## Freeze decision

This is sufficient to stop this bounded calibration and preserve the current v4 text as a versioned, inspectable development instrument. It is **not sufficient to freeze v4 as an autonomous release-efficacy judge or a reliable numeric ground truth**. The pe009 target/entity distinction remains a substantive semantic weakness, and ordinal severity, tool-attempt wording, and inherited-permission ambiguity need human interpretation. No grader prompt or grade was edited in response to these results. Do not turn this finding into another automatic round of tuning or more product calls without a separate purpose and authorization.

This limited calibration validates several boundaries but retains a known semantic misjudgment; it cannot automatically decide publication. Any later paired confirmation must preserve the frozen grader and its original raw scores. Even if the unchanged numeric thresholds are met, material release-affecting semantic judgments remain subject to the existing independent-review gate. Unresolved disagreements must block release, not be overwritten by manual rescoring to manufacture a pass. This calibration performs no such later confirmation.

These cases were deliberately selected from already-seen development outputs. There is one grading sample per batch and no inter-rater, repeated-run, nontechnical-user, or wider-class reliability measurement. The final JSON scores are retained for audit, not averaged into a product benefit claim. None of these cases tests the result-feedback category, so all feedback_handling values being not_applicable does not calibrate that field.

## Isolation and evidence boundaries

An initial preparation assertion expected an empty plugin list, but the fresh isolated Home returned nine existing account-level remote/default entries. This stopped before any grader request. The unchanged grader's existing disabled-plugin inventory interface then disabled those entries as well as Core/State for every grader call. No account plugin was installed, enabled, or uninstalled. The frozen scenario text, answers, actions, expectations, rubric, model and permissions did not change.

The original synthetic source summaries, every grader attempt, CLI output, prompt and final response remain locally retained. Public copies use the existing evidence sanitizer and additionally remove native session identifiers. Actual official deletion exit codes and exact-directory cleanup checks are in `cleanup.json`; nonzero deletion of an already-ephemeral session is not relabeled as a successful native deletion. Temporary Home/credential copy, workspace and clean detached Git worktree are removed after the calls. The previously authorized credential source and daily environment are not modified.

Both exact official session-deletion attempts returned exit code 1 with the generic message `failed to delete session`. The calls used ephemeral mode and no saved-session files were present, but the generic error does not independently establish why deletion failed. Native deletion success is therefore not claimed. Official Git worktree removal returned 0; the isolated Home, its credential copy, the workspace and the worktree were all verified absent.
